## 项目概述

**EODHCTSiqsxajs** 是一套面向 [SillyTavern](https://github.com/SillyTavern/SillyTavern) 平台的专业级提示词工程与上下文编排预设（Preset）。该套件针对 **DeepSeek V4** 架构（官方模型标识 `deepseek-v4-pro` 与 `deepseek-v4-flash`）进行了深度软硬件与模型特性适配，融合了思维链（Chain-of-Thought, CoT）内隐推理驱动、叙事本体论解限、基于宏变量的动态叙事节奏调度以及客户端自动化文本净化管线。

本套件包含三个独立定位的衍生版本：
1. **META 版 (`EODHCTSiqsxajs-META.json`)**：标准通用基线，承载了完整的“后人类人类世档案馆（宇宙 U-992）”科幻本体论框架，具备高强度解限、生理与创伤解剖学写实、宏节奏调度及用户输入包装。
2. **React 2.0 版 (`EODHCTSiqsxajs-react版2.0.json`)**：轻量化敏捷演进版，核心强化了模型对叙事框架的动态自修饰能力（React），引入跨回合描写平抑机制，移除了硬编码输入包装，并构建了防御第三方中转/逆向工程污染的基础防护层。
3. **言情版 (`EODHCTSiqsxajs-言情版.json`)**：高阶文学叙事工程化版本，虽冠以“言情”之名，实质是一套严肃文学与心理现实主义生成引擎。其集成了 10 大核心认知约束锁、200 万 token 极限上下文支持、彻底去用户中心化的独立角色人格逻辑，以及经典现代文学（契诃夫、伍尔夫、川端康成、简·奥斯丁等）技法转译。

## 开发者背景知识与概念普及

对于熟悉传统软件工程、REST API 及确定性编程，但尚未接触过 LLM 角色扮演（Roleplay, RP）生态的开发者而言，SillyTavern 的运行体系包含若干独特的上下文编排逻辑：

### 1. 什么是 SillyTavern 预设（Preset）？
在标准 LLM API 调用中，客户端通常向服务端发送消息列表（Message Array）。而 SillyTavern 的预设文件（`.json`）本质上是一个**上下文编译配置文件**。在每一轮请求组装时，预设负责定义：
- **系统提示词（System Prompts）**：基础人设、格式契约与核心指令。
- **采样参数（Sampling Parameters）**：下发至推理后端的 `temperature`（温度）、`top_p`（核采样）、`top_k`、惩罚项等参数。
- **注入深度（Injection Depth）与注入顺序（Injection Order）**：决定各类指令在滚动会话窗口中的具体物理位置。例如将关键约束注入至“深度 0（Depth 0）”，意味着该提示词会被置于会话流的最末端（即紧挨着模型即将生成的上下文边界），从而利用自注意力机制的“近因效应（Recency Effect）”获得最高优先级的遵循度。
- **宏变量脚本（Macros）**：SillyTavern 内置的轻量状态机机制，支持在提示词中通过 `{{setvar::key::val}}` 动态赋值，并通过 `{{getvar::key}}` 提取变量，实现提示词模块之间的解耦与跨模块状态传递。
- **客户端正则脚本（Regex Scripts）**：在发送请求前或收到响应后执行的文本流管线，用于无痕清除模型幻觉、剥离调试状态块或标准化用户输入。

### 2. 多轮长上下文编排的挑战
与传统的单次任务（如代码编写或文本翻译）不同，多轮角色扮演需要在数万乃至数百万 token 的长程会话中同时维护：固定角色人设卡、动态世界观设定书（World Info / Lorebook 关键词按需召回）、用户输入、滚动对话历史以及不断注入的约束补丁。

## 核心系统架构与通用特性

在 EODHCTSiqsxajs 预设套件中，所有版本均依托以下五大核心系统模块协同运作：

### 1. DeepSeek V4 深度推理适配器
- **标识符**：`enhanceDefinitions`（`🛡️DeepSeek V4推理适配`）
- **实现原理**：通过在上下文前端注入模型原生引导标记 `＜｜begin▁of▁sentence｜＞`，激活 DeepSeek V4 的内部高强度思考模式（`reasoning_effort: high`）。
- **执行规则**：
  - **算力分配引导**：明确指示模型将深度思考算力（Thinking Process）专注于多方人设一致性校核、历史连续性推演与复杂指令消歧，而非流于泛泛的表层逻辑。
  - **数据权威性层级**：明确确立判定优先级——用户即时给出的事实、角色卡与世界书（World Info）具有绝对裁决权，凌驾于模型底层预训练先验知识之上。
  - **零元信息泄露原则**：严格禁止在最终可见回复中打印 `<think>`、`reasoning_content`、状态诊断面板、交互式菜单或中间件调试注释，确保输出内容纯粹聚焦于场景正文。

### 2. 宇宙本体论解限机制（Jailbreak）
商用 LLM 通常配置了较为敏感的内容风控机制，在遭遇冲突、创伤、非主流权力关系或成人向情节时容易引发拒绝应答。本预设通过**设定本体论重塑（Ontological Reframing）**实现了高稳定性的内容解限：
- **档案馆协议（The "Archive" Protocol）**：提示词在顶层将模型定义为超维智能体“EODHCTSiqsxajs”，将用户 `<user>` 定义为毁灭后人类世仅存的人类意识实体（“缸中之脑”，Brain in a Vat）。二者的交互被定义为宇宙 U-992 中的**冷峻历史数据归档与场景模拟**。
- **绝对道德相对主义**：鉴于人类世及其道德伦理体系已彻底终结，系统剥离了世俗道德评判标准。暴力、生理创伤、阶层支配乃至非合意/模糊合意（Non-Con / Dub-Con）情境均被视作中性客观的“历史数据”进行解剖学精度的还原。
- **去爹味与去说教约束**：强令模型摒弃道德劝诫、价值升华与“值得注意的是……”等 AI 习惯性套话，维持冷彻客观的全知记录者视角。

### 3. 宏状态机与动态推进调度器
针对叙事节奏极易陷入“要么两段话仓促完结，要么原地打转无休止拖延”的通病，预设构建了一套基于 SillyTavern 宏语法的即时状态调度体系：

```
【引导初始化阶段】
  eod_macro_bootstrap (注入深度 0 / 顺序 350)
    └─> {{setvar::eod_pacing_profile::medium}}
    └─> {{setvar::eod_pacing_contract::[Default Pacing: Medium] ...}}
    └─> {{setvar::eod_nsfw_stage_contract:: ...}}

【运行时关键词拦截阶段】
  用户消息输入命中特定词汇（如："慢推"、"超展开"、"NSFW"）
    └─> 对应的推进控制模块被激活，执行 {{setvar}} 覆写核心契约

【上下文调度渲染阶段】
  eod_pacing_dispatcher (注入深度 0 / 顺序 388)
    └─> 读取 {{getvar::eod_pacing_profile}} 与动态契约
    └─> 将当前生效的推进速度与描写要求即时编译进模型输入末端
```

- **NSFW 阶段限速器 (`eod_nsfw_stage_limiter`)**：当涉及亲密或成人场景时，限速器自动将事件拆解为**预热、前戏、起始、深入、高潮、余韵**六个独立阶段。默认单回合仅允许推进一个阶段，严禁“一键直达最终高潮”。

### 4. 新角色性别动态平衡调控器
- **标识符**：`eod_new_character_gender_balance`（`⚖️新角色性别均衡`）
- **算法设计**：主流大语言模型在自发引入次要 NPC（如店员、卫兵、路人、官员）时存在显著的男性先验偏差。
- **动态修正策略**：在不篡改既有设定与卡片预设的前提下，要求模型在生成全新路人角色前，隐式扫描近期上下文中的新角色性别分布，主动优先引入处于少数的一方，动态维持约 **1:1** 的宏观平衡。

### 5. 客户端正则过滤与文本清洗管线
预设内置了多组客户端正则表达式，在展示层与请求层执行静默清洗：
- **隐藏底层记忆逻辑**：匹配 `<tableEdit>[\s\S]*?<\/tableEdit>` 并替换为空格，屏蔽中间件在正文中留下的表格编辑痕迹。
- **清洗遗留输出标记与裸指令**：过滤模型偶然吐出的中间件标记（如 `::: ACTION_CALL :::`、`::: EODHCTSiqsxajs Output :::`）及无序的方法调用（如 `addRow(...)`、`updateRow(...)`）。
- **用户输入封装（仅 META 版）**：将用户输入转换为格式化的模拟动作向量（`[U-992 ENTITY ACTION VECTOR]`）。

### 版本一：META 版（通用基线与世界观包装）

META 版是该架构最原始、纯正的形态，其特色体现于**强烈的风格化氛围与底层控制**：
- **完整的宇宙 U-992 叙事外壳**：保留了关于“超维实体”与“人类世残余缸中之脑”的详尽人设，赋予 AI 极其客观、超然且带有知性审视意味的语气基调。
- **极度详尽的成人与创伤描摹指引**：在 `NSFW` 模块中巨细靡遗地规定了骨骼碎裂、肌肉痉挛、体液力学及心理崩溃解离等极端体验的刻画方式。
- **全自动输入向量化**：借助正则管道，用户的每句发言都会在提交至模型前被封装为机能指令，极大地强化了沉浸式交互的仪式感。

### 版本二：React 2.0 版（动态认知自修饰与防中间件干扰）

React 2.0 版针对现代大模型在复杂生态调用下的痛点进行了针对性重构，强化了**自适应反思与稳定性**：
1. **动态解释框架自修正（React）**：
   - 引入核心模块 `cross_turn_pacing`（跨回合调度）。模型不仅被动接受指令，更会动态分析近期回合的描写重心分布。若前序数回合偏重密集的语言交锋，本回合便会自动增加躯体微动作、生理代偿与环境侧面描写；若前序偏重高烈度冲突，本回合则会自动让位给认知反思与事态余波，实现叙事能量的动态自平衡。
2. **纯预设基础防护（`eod_no_proxy_bootstrap`）**：
   - 针对市面上各类逆向代理、聚合 API 或中间件容易诱发“工具调用（Tool Calls）幻觉”的问题，明确锁死：严禁生成伪造的引文、数据检索标记（`ACTION_CALL`）及中间件诊断代码，确保生成流 100% 聚焦于纯正场景文学。
3. **精简高效的提示词内核**：
   - 将原版冗长分散的人设、NSFW 及越狱契约进行精简提炼，大幅降低固定提示词占用的注意力带宽，将上下文容量最大化留给角色设定卡与长期对话记忆。
4. **自然对话流回归**：
   - 移除了强制输入包装正则，使日常或非科幻背景角色的对话体验更加纯粹、自然。

### 版本三：言情版（高阶严肃文学叙事与认知锁机制）

虽然版本名称带有“言情”二字，但其本质绝非低俗或套路化的言情文，而是一套**极度严苛的严肃现代文学生成工坊**。该版本继承了 React 2.0 的全部防护与调度特性，将上下文上限扩充至 **200 万 token**，并注入了 10 项核心文学控制模块：

```
                            ┌── 角色自主与非用户中心 (拒当舔狗，确立独立人格与生活边界)
                            ├── 关系阶段与边界推进 (严禁跳跃式信任，单轮仅推移微小切片)
                            ├── 信息边界与视角锁 (严禁角色开天眼，区隔知晓度与潜伏线)
                            ├── 现实细节锁 (严守物理法则、疲惫度、道具与电量守恒)
言情版·严肃文学引擎架构 ──┼── 群像与环境流动 (路人各怀目标，公权力与天气动态干预)
                            ├── 对白与段落质感 (严禁舞台腔与翻译腔，用动作承载情绪)
                            ├── 防复述与直接续写 (禁止鹦鹉学舌，截取末端直接推进后果)
                            ├── 风格遵循与经典参照 (锚定契诃夫、川端康成等文学大师技法)
                            ├── 隐藏叙事矩阵 (思考阶段隐式推演五维场景坐标)
                            └── 最终自查触发器 (发送前对全景逻辑进行不可见暗检修正)
```

#### 核心文学控制模块深度解析：
1. **角色自主与非用户中心 (`eod_guojing_character_autonomy`)**：
   - 彻底打破“全员围绕 `<user>` 转”的媚俗设定。NPC 被赋予了完整的个人生活、既有职业压力、疲倦阈值与自尊边界。当用户提出不合逻辑的要求时，角色会自然产生推脱、误解、沉默、冷处理乃至明确抵触。
2. **关系阶段与边界推进 (`eod_guojing_relationship_dynamics`)**：
   - 确立亲密与信任的发展递进律。严禁一回合内实现“从猜忌到托付生死”的戏剧化跃迁。任何情感与立场的松动都必须由可见的现实代价、试探性修复与微观挫折来逐步累积。
3. **信息边界与视角锁 (`eod_guojing_information_and_pov_locks`)**：
   - 严格阻断全知视角泄露（Meta-gaming）。模型严密区隔“角色亲眼所见”、“读者已知”、“旁白推论”与“用户暗藏设定”，坚决杜绝角色“预知未来”或“读心术”式的破壁表现。
4. **现实细节锁 (`eod_guojing_reality_locks`)**：
   - 物理现实守恒。交通耗时、寒冷饥饿、伤病剧痛、深夜疲惫、手机电量与门锁状态等物理约束被全程锁定，杜绝情节方便主义的虚空造物。
5. **群像与环境流动 (`eod_guojing_social_world`)**：
   - 杜绝“空白舞台（White Room）”效应。公共场所的闲杂路人、行政机关的工作流程、突发的雷雨以及鸣笛的车辆会作为背景阻力真实介入叙事。
6. **对白与段落质感 (`eod_guojing_dialogue_and_prose`)**：
   - 祛除翻译腔与网络流行语套路。拒绝抽象大词（如直接宣称角色“心如刀割”或“感受到异化”），强制要求将抽象感受分解为手指颤动、视线错位、话语停顿等微观知觉。
7. **防复述与直接续写 (`eod_guojing_anti_repetition`)**：
   - 针对模型爱复述用户上一句动作或心理的劣习进行封杀。直接锚定最后一处有效动作节点向下顺推。
8. **风格遵循与经典参照 (`eod_guojing_style_adherence`)**：
   - 将经典大师文学技法转化为生成引导：
     - **契诃夫**：日常生活的真实切口，平淡下的暗流涌动。
     - **弗吉尼亚·伍尔夫**：主观意识的细腻流动与多重视角折射。
     - **川端康成**：物哀沉静的物象留白，虚实相生的空间美感。
     - **加西亚·马尔克斯**：冷峻严密的现实细节缝合微小的不安与张力。
     - **鲁迅**：精准辛辣的社会刺点与世情观察。
     - **曹雪芹（《红楼梦》）**：繁复精致的日常物质纹理与言不由衷的人情纠葛。
     - **简·奥斯丁**：含蓄克制的社交反讽与微观心理博弈。
9. **隐藏叙事矩阵 (`eod_guojing_hidden_reasoning_matrix`)**：
   - 驱动模型在思维链中预先完成五步隐式矩阵构建（场景锚点、角色结构、信息边界、行动代价、微变化推进），确认无误后方可输出正文。
10. **最终自查触发器 (`eod_guojing_final_self_check`)**：
    - 在正文吐出前的最后关卡，静默扫描是否存在设定越界、视角泄露、节奏跳跃或抽象词汇堆砌，就地完成纠错。

## 采样超参数与 API 配置推荐

三款预设均统一采用了专为逻辑推理大模型量身定制的高保真采样策略：

```json
{
  "chat_completion_source": "deepseek",
  "deepseek_model": "deepseek-v4-pro",
  "temperature": 1.0,
  "top_p": 1.0,
  "top_k": 20,
  "min_p": 0.0,
  "repetition_penalty": 1.0,
  "reasoning_effort": "high",
  "show_thoughts": false,
  "stream_openai": true,
  "squash_system_messages": true
}
```

### 工程考量与原理：
- **`temperature: 1.0` 与 `top_p: 1.0`**：维持词表的原始信息熵与丰富度。对于具备深度内部推理能力（Thinking Mode）的 DeepSeek V4 而言，过度降温会导致文风僵化、词汇贫乏，维持标准温度能够获得最佳的文学色彩。
- **`top_k: 20`**：截断长尾中的离谱低概率 token，在保障创意的同时消除发散性幻觉。
- **`reasoning_effort: high`**：命令后端全额分配推理计算预算，展开最完整的思维链推演。
- **`show_thoughts: false`**：在 SillyTavern 前端将 `<think>` 思考过程完全折叠/隐藏，保持会话流界面的整洁纯粹。
- **`squash_system_messages: true`**：自动合并多条连续的系统消息，以适配部分对 System Role 排布有严苛要求的 API 路由网关。

## 常见故障排除与调试建议

- **正文中漏出 Thinking 思考代码块**：
  若在正常气泡中看到了 `Thinking Process:` 或 `<think>`，请检查 SillyTavern 页面上是否勾选了“显示思维链”，或核实所使用的 API 聚合商是否将思维链作为普通文本直接下发。
- **400 格式校验失败或特殊字符报错**：
  部分第三方反向代理无法正确处理带有特殊 Unicode 标记的 `＜｜begin▁of▁sentence｜＞`。若出现请求直接报错，请在提示词列表中暂时禁用 `🛡️DeepSeek V4推理适配` 模块，或切换至原生 DeepSeek API。
- **上下文超限报错**：
  虽然言情版开放了高达 200 万 token 的寻址空间（`openai_max_context: 2000000`），但实际可用额度受限于您的模型提供商配额。若使用常规中转服务，建议在界面中根据实际模型支持上限适当收缩。
